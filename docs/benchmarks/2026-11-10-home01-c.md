# home01 C 规模基准测试报告（2026-11-10 至 11）

## 测试范围与环境

2026-11-10 至 11 在 home01 使用 `ohlc` 账号，对 ohlc、ClickHouse、InfluxDB、
Aerospike CE 进行 1.536 亿行对比。测试使用 C 的证券数、时间数、查询、计时与字段核对方法，
以真实行情作为数值种子。验收方法见[设计文档第 19.3 节](../design.md#193-性能验证)；
本轮不等同于其中规定的合成生成器正式 C 验收，也不完成 S/L、冷读或断电验证。
所有服务、客户端与数据准备进程均以 `ohlc` 账号运行；root 编排仅设置 cgroup、CPU 与文件权限。

主机为 RHEL 9.4、双路 Xeon Platinum 8260（48 个物理核、96 个逻辑 CPU）、约 125 GiB RAM；
测试盘为 KIOXIA EXCERIA PLUS G2 1 TB NVMe，XFS `noatime`。服务均绑定环回地址；
被测引擎 `src/` 源码树标识为 `1aedef27bac8f8442e111c72e4f2c8d8b4058bb7`，与正式版引擎实现一致。
被测原生库 SHA-256 为 `4416dc494bcb4d2bb9ae7e0175012166886329e1dad0203554ac7783332f2cf0`；
测量使用该证据二进制，Release 构建的 13 项 CTest 全部通过。
竞品版本固定为 ClickHouse 26.10.2.103、InfluxDB 2.7.12、Aerospike CE 8.2.0.1，
Aerospike Python 客户端为 19.3.0；下载地址、软件指纹、编译选项和工具指纹随证据保存。

## 数据、配置与执行方法

- 原始输入 `/hd01/quotation` 只能读取。数据准备与测量进程额外通过 systemd `ReadOnlyPaths`
  将其挂为只读；软件、种子、数据库和证据均位于 `/ssd02/ohlc-benchmark-20261110`。
- 选择 2022 年 3–6 月文件、排序后的前 256 只证券，以 `000001.SZ` 实际出现的前 64 个交易日期
  （2022-03-01 至 2022-06-06）为模板，每日选择 09:31–11:30、13:01–15:00 的 240 个时间。
  09:30 不进入该派生数据集；不改写、舍入或回写原始时间。
- 价格乘 10,000，成交量乘 1，成交额乘 100，以十进制 half-even 舍入并检查整数范围；
  `adjust_factor=1000000`，`reserved=NULL`，`flags=127`。源 `idx`、`pre_close` 不映射到业务列。
  稠密种子缺行或六个来源字段缺失时，使用同一时间的基准证券值。256 × 15,360 个种子中
  有 2,160 行使用替代值；成交额有 4,855 次小数舍入，价格与成交量没有舍入损失。
- 对虚拟证券 s、时间序号 t，使用种子 `[s % 256, t % 15360]`；四个价格统一增加
  `floor(s/256)*100 + ((17*s + 31*floor(t/240)) % 101) - 50`，成交量和成交额统一乘
  `1 + floor(s/256) % 7`。证券名为 `S00000`…`S09999`。这是确定性扩展数据，不是
  10,000 只真实股票；重复模板会影响压缩率，空间结果不得外推为原始全市场行情的压缩率。
- 只预存约 240 MiB 种子；1.536 亿行由同一生成器流式导入，期望查询由同一规则生成。
  1,023 个输入文件的 SHA-256、大小与 mtime、种子指纹和日期列表保存在 `seed/manifest.json`。
- 服务绑定 CPU 0–15，独立进程客户端绑定 CPU 24–39；测量时将对应 SMT 兄弟 CPU
  48–63、72–87 下线，结束后恢复。服务 cgroup 上限 32 GiB，服务与客户端均禁止交换。
  ohlc 引擎预算 24 GiB、块缓存 64 MiB、网络预算 1 GiB；全部系统串行使用同一块 `/ssd02` NVMe。
- 导入为单客户端。ohlc、ClickHouse 和 InfluxDB 每次导入 8 个时间 × 10,000 行；Aerospike 按其证券/日记录
  一次构造完整 240 行 blob，再以每批 1,000 条记录写入，避免用历史导入模拟大量日内覆盖。
  各系统仍按调用至确认的累计时间加最终检查点、合并或压实等待报告导入速率，另外报告总墙钟。
- ohlc 使用固定行存储，当前版本不支持压缩，也没有压缩配置项。
  ClickHouse 使用按 `(ticker,time)` 排序的 MergeTree、LZ4 和完整
  `(time,ticker)` 投影，开启 `fsync_after_insert` 与 `fsync_part_directory`；InfluxDB 使用
  ticker tag、整数 field 与原生 TSM 编码，WAL fsync delay 为 0。Aerospike 使用证券/日 blob，
  640,000 条记录承载 153,600,000 根 K 线，未压缩，开启 read page cache，查询由服务端截取 blob。
  Aerospike CE 写入确认不等同于其余三库的同步持久写入，导入和实时写入结果不得混作持久性排名。
- 热延迟在每次计时前执行相同查询并完整核对；每次计时包含全部返回字段解码，InfluxQL
  结果排序也计入。R1、R60、R240、R4800、RFULL、X 各最多 1,000 个样本；
  吞吐按 1/4/16 个独立进程、1 秒预热、3 × 5 秒测量，变异系数超过 5% 时重测一次。
  单次延迟不计请求准备与核对耗时；吞吐计入准备、结果解码、行数/边界检查及每 16 次的全字段核对。
  这是包含各客户端协议开销的应用观测结果，不能解释为纯引擎执行时间或已耗尽服务端吞吐上限。
  实时写入为 301 个新时间横截面，每批 10,000 行，每批确认后完整读取核对。
  每批从发起写入起至少间隔 1 秒；下一批生成与编码另占时间，实际频率略低于每秒一批。
  实时延迟只统计调用至确认，未含编码、随后读回与节流；总墙钟及 CPU/I/O 差值另存原始记录。
  少于 1,000 个样本不报告 p99；无法可靠核验的受控冷读标为不可比。
- ClickHouse 横截面查询设置 `optimize_read_in_order=0`，访问 `cross_order` 投影。
  首、中、末时间的 `EXPLAIN projections=1,indexes=1` 随证据保存。
- InfluxDB 使用 10 秒缓存快照静默阈值和 60 秒全量压实静默阈值；缓存与压实活动/队列归零后
  连续观察 65 秒，期间出现活动则重新等待，全部等待计入导入完成时间。
- InfluxDB 的 X/4 吞吐变异系数为 5.62%，标为不稳定；X/16 触及 32 GiB cgroup 上限并发生 OOM，
  该组失败，不使用未完成轮次计算吞吐。实时写入组使用独立重启的服务，起始数据为 153,600,000 行；
  301 批写入与全字段读回通过，但第 15 个 shard 的 full queued 指标为 1，压实完成条件不满足。
  因此只报告实时写入组，不将整个执行单元记为通过，也不报告其压实后空间。

## 结果选取与核验

工具入口为 `tools/benchmark_install.py`、`tools/benchmark_quotation.py prepare` 和
`tools/benchmark_home.py`，后者必须在目标主机上显式指定测试根目录与新轮次名称，
不会覆盖已有轮次目录或删除数据库。原始 JSONL、配置、进程与 cgroup 采样保留在该根目录
的 `results/<轮次>/`。2026-11-10 至 11 的最终选取为 `c01/ohlc`、`c02/clickhouse`、
`c03/influxdb`、`c03/aerospike`，另取 `c04/influxdb` 已完成的实时写入组。
所有测量和无效样本均可按证据目录复核。源文件事后复核的 1,023 个 SHA-256、大小和 mtime 全部一致，
种子指纹一致；1,024 个标量/向量生成样例及 20 个纵向/横截面一致性检查通过。
测试服务已停止，测试端口关闭，各轮 SMT 状态均恢复，96 个逻辑 CPU 全部在线。

## 导入 153,600,000 行

总墙钟从流式导入开始，包含负载生成、编码、写入和最终整理等待。
确认速率的分母只含累计写入调用和最终整理；两者口径不同。

| 系统 | 总墙钟（秒） | 写入调用累计（秒） | 最终整理等待（秒） | 确认加整理速率（行/秒） |
| --- | ---: | ---: | ---: | ---: |
| ohlc | 61.003 | 36.432 | 0.285 | 4,183,341 |
| ClickHouse | 371.892 | 289.525 | 75.019 | 421,348 |
| InfluxDB | 2,732.708 | 2,007.925 | 130.184 | 71,839 |
| Aerospike CE | 319.318 | 12.048 | 5.008 | 9,005,571（确认语义不同） |

Aerospike blob 编码准备累计 280.877 秒，InfluxDB line protocol 编码累计 587.142 秒；
因此不能用较高的确认速率替代用户实际等待的总墙钟。Aerospike CE 的数字不构成同步持久导入优势。

## 结论与适用范围

本次结果表明，在该数据派生规则、热读、单机环回协议和配置下，ohlc 的导入总墙钟、六类单读者
p50 及 16 读者 S/X 吞吐均优于本轮对应竞品值；4 读者 S 则为 Aerospike 更高。
结论只适用于这些已测场景，不外推到冷读、其他压缩分布、更多并发、分布式复制或断电持久性。
